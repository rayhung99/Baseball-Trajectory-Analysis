# 演算法與功能穩定性排查 — 2026-10-06

本輪檢查裝置端球速／TTC 計算、影片 metadata／解碼／疊圖入口、原生結果轉換、分析進度與畫面生命週期，延續 [前一輪審查](release-review-2026-09-16.md)。修正以下可重現的問題，並增加輸入邊界保護；沒有更換辨識模型、調整球速物理常數或更動距離校正範圍。

這份紀錄證明列出的情境受到測試保護，不能保證所有影片都辨識正確或球速沒有誤差。尚未完成本輪 iOS 原生整合建置與實拍精度驗證。

## 修正與證據

| 問題 | 修正 | 驗證 |
| --- | --- | --- |
| NaN／Infinity 距離、負值或超量跨步補償、反序時間戳仍可能產生球速；舊版把有效距離硬補成至少 1 公尺。 | 球速入口拒絕無效校正、時間戳與非有限座標，回傳錯誤且不提供球速。 | 新的 Swift 校正／時間戳案例在舊版失敗，修正後通過。 |
| TTC 只排除過短估計；弱球面積成長可用 0.8 秒 TTC 蓋掉 0.5 秒的未受物理限幅的終點估計。 | 沿用既有誤差容忍值，雙向比對；不一致時保留終點時間，記錄 `rejected_long_vs_endpoint`。 | 合成案例在舊版得到 0.8 秒，修正後保留 0.5 秒；既有短／限幅 TTC 案例也通過。 |
| TTC 擬合對所有觀測兩兩計算斜率，4096 筆形成 8,386,560 個配對，且觀測順序會影響成長檢查。 | 排除非有限／負時間、非有限面積與重複時間戳；依時間排序，最多取 64 個均勻分布的真實觀測，配對最多 2016 個。 | 4096 筆合成觀測、反序、NaN 污染、重複時間戳與插值排除案例通過。診斷時舊版擬合約 10 秒，修正後約 11 毫秒（macOS、未最佳化編譯；不是手機或完整分析效能）。 |
| 只靠點數推測時間或物理限幅時，結果未必顯示資料品質警告。 | 這兩類情境也設定既有品質警告欄位。 | 無可靠時間錨點的案例會回報警告。 |
| `speed_info.error` 被結果 adapter 丟棄；沒偵測到球或缺少有效球速也可進入成功流程。 | 保留原生錯誤語意，拒絕空結果、缺少球速與非有限／非正球速。 | 實際 adapter 的錯誤與空結果測試，在修正前失敗、修正後通過。 |
| 原生已回傳整體進度，前端又按階段換算，50% 被顯示成 25%。 | 直接使用整體百分比，限制 0–100%，處理非有限值。 | 各階段與 NaN／Infinity 案例通過；既有架構檢查同步更新。 |
| 快速連點或兩個 hook 實例可同時啟動原生分析；進度事件沒有分析 ID，會互相干擾。卸載後也可能交付晚到結果。 | 同步鎖定原生分析入口、清除監聽器，取消／卸載後拒絕結果；分析畫面同步鎖定，避免重複請求提前清除忙碌狀態。 | 重複啟動與卸載案例原先失敗；修正後連點、跨實例、取消、原生失敗、後續重試與畫面狀態案例通過。 |
| 影片 metadata 直接轉整數，在非有限或超出整數範圍時會觸發 Swift trap。 | 以可失敗轉換檢查 fps、尺寸與影格數，檢查正有限 duration；capture fps 在轉整數前限幅。疊圖共用已驗證 metadata，對角線計算改用 `hypot`。 | 數值邊界測試及 AVFoundation 正常／損壞 MP4 解碼通過；未以真實畸形 metadata MP4 覆蓋每個邊界。 |

TTC 取樣降低配對成本，也改變長序列的斜率分布；合成案例可確認理想模型的答案一致，不能取代含誤偵測、模糊與遮擋的實拍比對。

## 上架前剩餘驗證

1. 使用者自行閱讀、接受 Xcode 授權後，重新跑 Release 建置與 `npm run check:video:ios`（需有啟動中的 iOS 模擬器），再完成簽署 Archive 與 TestFlight。
2. 使用真實投球影片及獨立可信的測速基準，記錄每球校正距離、跨步補償、拍攝角度、fps、原始影片、球速誤差及是否偵測失敗；覆蓋普通／慢動作、不同距離、光線、遮擋與手機。沒有這批資料，無法訂出可對外宣稱的誤差範圍。
3. 球種、位移、好球帶與 3D 球路也需各自對照基準；球速測試成功不代表這些估測已驗證。低品質提示仍須保留。
4. 實機檢查背景／前景切換、長影片、低儲存空間、權限拒絕、快速操作與分享／歷史重播。影片仍使用暫存目錄，系統清除後不能保證永久重播。

`cancel()` 現在停止進度與結果交付，仍不會中斷 Swift 分析；原生工作完成前會保留分析鎖。現有介面沒有取消按鈕，新增按鈕前需要完整實作原生取消與資源清理。
